I Installed Windows 10 From Scratch in My OS Fundamentals Class

Bootable USB, BIOS, clean install, and a mid-lab detour to GitHub to find a working Windows key. Here is how it all went.

One of my on-campus classes at IHCC this year is OS Fundamentals. Most of it is theory and concepts, but one of the labs was hands-on in a way I hadn't done before, we were given lab PCs and had to create a bootable Windows 10 USB drive, get into BIOS, configure the boot order, and do a full clean install of Windows from scratch. I had seen it done before but never actually done it myself, so this was the first time I had to figure it out with my own hands.

Creating the Bootable USB

The first step was creating the installation media. We used the Windows Media Creation Tool, which is Microsoft's official tool for downloading Windows and writing it to a USB drive. The process is pretty straightforward: you run the tool, select "Create installation media for another PC", pick your language and edition, point it at your USB drive, and it downloads the Windows ISO and writes everything to the drive automatically. The download takes a while depending on your connection, but once it's done you have a bootable USB ready to go.

The tool handles everything behind the scenes so you don't have to manually flash an ISO or mess with partitioning the drive yourself. It's the easiest way to do it for Windows specifically.

Getting Into BIOS

Once the USB was ready the next step was getting into BIOS on the lab PC. BIOS is the firmware that runs before the operating system loads, it controls hardware settings and, importantly for this, it controls what the computer tries to boot from first. By default most PCs are set to boot from the internal hard drive, so to boot from a USB you have to either change the boot order in BIOS or use the one-time boot menu.

The key to get into BIOS varies by manufacturer. On these lab PCs it was pressing F11 as the computer powers on, before Windows has a chance to start loading. Once you're in, you find the boot order settings and move the USB drive to the top so the PC tries it first on the next restart.

The Install Process

With the USB at the top of the boot order, restarting the PC booted into the Windows installer instead of the existing OS. The installer walks you through language and region settings, then asks where you want to install Windows. For a clean install you delete the existing partitions and let Windows create fresh ones on the drive. From there it copies files, installs features, and reboots a couple of times before landing on the Windows setup screen.

This is where I hit a wall. The installer asked for a Windows product key to activate the installation and continue. We weren't given keys for the lab, so I had to figure something out.

The GitHub Detour

I did some searching and found a GitHub repository that had a list of generic Windows keys. These are not pirated keys, they are publicly known generic keys that Microsoft has used for volume licensing and testing purposes for years. They get Windows installed and past the activation prompt, though the copy runs unactivated, which just means you get a watermark on the desktop and some personalization features are locked. For a lab environment where the goal is just to complete the install, that's perfectly fine.

Finding that and understanding what it actually was, a generic key, not a cracked license, was its own small lesson. Knowing the difference between a generic volume key and actual piracy is useful context in IT work.

What I Took Away From It

The install itself is not complicated once you have done it, but there is a lot of context you need to understand to do it confidently. Knowing what BIOS is and why boot order matters, understanding what a bootable drive actually does, knowing what a product key is for and what happens when you don't have one, none of that is obvious if you have never been through it before. This lab forced me to understand all of it at once instead of just watching someone else do it.

It also reinforced something I already believed from my IT internship: the best way to learn this stuff is to actually do it, run into a problem, and figure it out. The Windows key situation was a small problem, but solving it on the spot in the middle of a lab is exactly the kind of thing that sticks with you.
