My Scripting Fundamentals Final: A Secure User Manager in Python

For my intro Python class final, I built a multi-file CLI app that handles user registration, hashed passwords, CSV import/export, and scans for credential leaks.

This was the final project for my Scripting Fundamentals class, an intro to Python course. The assignment was open-ended enough that I wanted to build something that actually felt useful rather than just a toy script. I landed on a command-line user management system that ties together a bunch of the things we learned over the semester: working with external libraries, databases, file I/O, and web scraping.

The finished project is split across six files, each handling a different piece of the app. Here's how it all fits together.

What It Does

When you run the app you get a simple numbered menu in the terminal: 

 Secure User Manager
1. Register
2. Login
3. Export Users
4. Import Users
5. Check for Leaks
6. Exit

From there you can register new users with password validation, log in, export the user database to a CSV, import users from a CSV, and run a leak check that scrapes a URL and flags any users whose credentials appear in the results.

The File Structure

I split the project into six files to keep things organized and practice writing modular code, something that got drilled into us throughout the class.

  • main.py — the entry point, runs the menu loop and ties everything together
  • models.py — defines the database schema using SQLAlchemy
  • db_setup.py — initializes the SQLite database and manages sessions
  • auth.py — handles registration and login with bcrypt password hashing
  • file_io.py — exports and imports users via CSV
  • leak_checker.py — scrapes a URL and checks if any user credentials appear in the results

Password Security with bcrypt

Passwords are never stored in plain text. Before saving a new user to the database, the app hashes the password using bcrypt, a hashing algorithm designed specifically for passwords that's intentionally slow to make brute-force attacks harder. When someone logs in, bcrypt compares the entered password against the stored hash without ever decrypting it.

On top of that, registration enforces a basic password policy, at least 8 characters, one uppercase letter, and one number: 

if len(password) < 8 or not any(c.isupper() for c in password) or not any(c.isdigit() for c in password):
    print("❌ Password must be 8+ chars, include a number and uppercase letter.")
    continue

The Database Layer

User data is stored in a local SQLite database using SQLAlchemy. The User model has three fields, username, email, and password hash, each enforced as unique so no duplicate accounts can be created. SQLAlchemy handles all the SQL under the hood, which meant I could focus on the logic rather than writing raw queries.

CSV Import and Export

The app can dump all registered users to a CSV file and read them back in. This was one of the more straightforward parts of the project but also one of the most practical, it shows how you'd back up or migrate user data between environments. The export includes the hashed passwords, so imported users can still log in normally without their original passwords being exposed.

The Leak Checker

This was the part that tied back to the earlier scraping assignment. The leak checker uses requests and BeautifulSoup to fetch a URL, pull all the text from the page, and then scan it for any usernames or email addresses that match registered users. If it finds a match, it flags that account as potentially compromised. 

for user in users:
    if re.search(user.email, text) or re.search(user.username, text):
        leaked.append(user)

In the final version I pointed it at a mock URL for testing, but the idea is that you'd swap in a real paste site or data breach dump to check against. It's a simplified version of how tools like Have I Been Pwned actually work.

What I Learned

This project pulled together pretty much everything from the semester in one place, classes and models, database sessions, file handling, web scraping, and organizing code across multiple files. The part I found most interesting was the security side: learning why you never store plain text passwords and how hashing actually works in practice rather than just in theory.

It's also the first Python project I've built that felt like something resembling a real application rather than a script. Splitting it into modules and having each file do one job made the whole thing a lot easier to debug and build on. That's a habit I want to carry forward.
