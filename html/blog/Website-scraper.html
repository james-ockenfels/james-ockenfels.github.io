How I Built a Bot That Could Bypass Bot Detection

For a web scraping assignment in my scripting fundamentals class, I had to build a scraper that could get past the bot protection on real websites. Here's what I learned.

In my scripting fundamentals class, we were given an assignment that seemed straightforward at first: write a bot to scrape data from a few websites. The catch was that the sites we were targeting: Amazon, DoorDash, and Ticketmaster, all have bot protection. So the real challenge wasn't just scraping, it was scraping without getting caught.

(Quick note: I was supposed to turn this in on Apirl 5th but somehow forgot about it until April 14th, Oops.)

Version 1: The Obvious Bot

My first attempt was simple and naive. I used Python's requests library to fire off a GET request to each URL with no headers, no cookies, nothing. exactly what a bot looks like to any halfway decent detection system. 

import requests
from bs4 import BeautifulSoup

urls = [
    "https://www.amazon.com",
    "https://www.doordash.com",
    "https://www.ticketmaster.com"
]

for url in urls:
    print(f"\nScraping {url} with obvious bot behavior...\n")

    try:
        response = requests.get(url, timeout=10)
    except requests.exceptions.RequestException as e:
        print(f"Request error: {e}")
        continue

    if response.status_code != 200:
        print(f"Blocked or redirected! Status code: {response.status_code}")
        continue

    soup = BeautifulSoup(response.text, "html.parser")
    title = soup.title.string if soup.title else "No title found"
    print(f"Title: {title}")

As expected, all three sites blocked it immediately. No headers means no user-agent string, which is one of the first things bot detectors check for. The responses came back with non-200 status codes, the sites knew exactly what was happening and shut it down before any real data could be pulled.

Why It Got Caught

When a real browser visits a website it sends a bunch of information along with the request, things like the user-agent (which browser and OS you're using), the window size, and various JavaScript properties that indicate a human is in control. A bare requests.get() call sends none of that. To bot detection systems, it's basically a giant neon sign that says "I am a script."

Version 2: The Stealth Bot

For the second version I switched to Selenium, which actually controls a real Chrome browser. That alone helps a lot, but the key was adding a few extra tricks to make the browser look as human as possible. I used a YouTube tutorial to figure out the browser setup side of things. 

from selenium import webdriver
from selenium.webdriver.chrome.options import Options
from selenium.webdriver.common.by import By
import time
import random

def setup_stealth_browser():
    options = Options()
    options.add_argument("--disable-blink-features=AutomationControlled")
    options.add_argument("user-agent=Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/122.0.0.0 Safari/537.36")
    options.add_argument("window-size=1920,1080")

    driver = webdriver.Chrome(options=options)
    driver.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {
        "source": """
            Object.defineProperty(navigator, 'webdriver', { get: () => undefined })
        """
    })
    return driver

def stealth_scrape(url):
    print(f"\nTrying stealth scrape on {url}...")
    driver = setup_stealth_browser()
    try:
        driver.get(url)
        time.sleep(random.uniform(3, 5))
        title = driver.title
        print(f"Title: {title}")
    except Exception as e:
        print(f"Failed to scrape {url}: {e}")
    finally:
        driver.quit()

urls = [
    "https://www.amazon.com",
    "https://www.doordash.com",
    "https://www.ticketmaster.com"
]

for url in urls:
    stealth_scrape(url)

This version worked perfectly on all three sites. Here's what made the difference:

  • Disabling AutomationControlled — Chrome sets a flag when it's being driven by automation. This argument disables that flag so sites can't detect it.
  • Custom user-agent — sets a realistic browser string so the request looks like it's coming from a normal Chrome install on Windows.
  • Window size — headless browsers often report unusual dimensions. Setting a standard 1920x1080 size looks more human.
  • Hiding the webdriver property — using a Chrome DevTools Protocol command to override navigator.webdriver so it returns undefined instead of true, which is another common bot detection check.
  • Random delay — waiting a random 3–5 seconds before grabbing data mimics the natural pause of a human reading the page.

What I Took Away From It

This assignment was a good lesson in how bot detection actually works, and how thin the line is between a script and a convincing fake browser. Most basic detection is just checking for things a real browser would always have. Once you start providing those signals, you can get surprisingly far.

It also made me think more carefully about the defensive side of things. If I were building a site that needed to block scrapers, I'd need to look beyond just user-agents and JavaScript flags, because as this project shows, those are pretty easy to spoof.
